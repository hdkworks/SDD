# 在庫管理システム の30日導入プラン

2026-10-23 に、第1週は自分で組み、第2〜4週は AI の素案を自分で直した。

## 第1週（1〜7日目）体験

| 曜日 | タスク | 7つの工程との対応 | 時間目安 |
|------|--------|------------------|----------|
| **月曜日** | リポジトリを作り、「在庫管理システム」の名前と背景を3行書く | ①原則決定（簡略版） | 10分 |
| **火曜日** | 想定ユーザーと主要機能を箇条書きで足す | ②要件定義 | 10分 |
| **水曜日** | ブラウザの AI に README を貼り、「不明な点を5つ質問して」と頼む | ③AI と対話 | 10分 |
| **木曜日** | 主要機能を、チェックボックスのタスクに分ける | ④タスク分解 | 10分 |
| **金曜日** | チームで README をレビュー。1週間を振り返る | ⑦レビュー | 10分 |

## 第2週（8〜14日目）習慣化

「今日 README 更新した？」がチームの自然な会話になり、週次レビューが定例になる

- [ ] 毎朝 README を開き、AI に1行追加させる
- [ ] 朝会の冒頭で「昨日 README 更新した人？」と聞く
- [ ] 金曜に README を見ながら1週間を振り返る

## 第3週（15〜21日目）プロセス改善

変更の出し方と見方が決まり、仕様の品質を仕組みで守れる

- [ ] 承認の方法（1〜2名）を決めて README に書く
- [ ] Pull Request のテンプレートを置く
- [ ] Markdown の文法とリンク切れの自動チェックを入れる（任意）

## 第4週（22〜30日目）定着と評価

30日の成果が数字で見え、次に何をするかを自分たちで決められる

- [ ] PR の数・レビューに参加した人数・マージまでの時間を数える
- [ ] 振り返り会で、うまくいったこと・いかなかったことを言葉にする
- [ ] 90日プランへ進むか、30日をもう一周するか決める

型：書籍『仕様駆動開発 実践入門』第5章の最初の1週間と、SDD リポジトリの 90日間導入プランの前半。
